# 1.1.0 — implementations() registry removed

**Date:** 2026-10-15

**Changed**

- Removed the `implementations()` helper entirely from `src/helpers.php`. It was
  an aliased class-registry (the renamed `app()`): registering validated that
  each class-string `is_a()` the aliased target and stored the list in `reg()`
  under `implementations.<name>`; resolving returned class-strings by suffix
  selector.
- The only consumer was `strukt/cache`, which now uses `app()` container
  bindings instead (see that package's changelog).

**Why**

- `base` now owns a Laravel-style `app()` container accessor. Keeping a second,
  parallel registry (`implementations()`) alongside the container invited
  confusion between "resolve a class-name registry entry" and "resolve a
  service", and `implementations()` existed only to serve the cache driver
  registry. Folding that into the shared container removes a redundant layer.

**Documentation**

- `docs/helpers.md`: removed the `implementations()` section; the `alias()`
  examples it carried now live in `base`'s README.
- `README.md`: dropped `implementations()` from the additional-helpers note.

**Tests**

- `tests/Unit/HelpersTest.php`: unchanged — it never covered `implementations()`.
  The `commons` suite stays at 20 passing.

**Public API impact**

- Breaking: `implementations()` no longer exists. Use `app()` (the container)
  or a package's own `reg()`/registry instead.
