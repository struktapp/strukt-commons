# 1.1.0 — Low-level primitives moved to strukt/base

**Date:** 2026-10-15

**Changed**

- commons now requires `strukt/base` and no longer re-declares the lowest-level
  primitives. `alias()`, `helper_add()`, `raise()`, `is_map()`, `notnull()`, and
  `negate()` are provided by `base`; the duplicate `Strukt\Raise` class was
  removed (base's `Strukt\Raise` is used instead).
- The `app()` implementation registry (and its `app.*` registry key) was
  removed rather than kept alongside the container accessor that now lives in
  `base`; see [implementations() registry removed](1.1.0-remove-implementations.md).

**Why**

- Both `base` and `commons` declared the same global functions behind
  `function_exists()` guards with different semantics, so the effective
  behaviour depended on Composer's autoload-file order. `base` is the lower-tier
  package, so it becomes the single owner; `commons` builds on it.
- `base` now owns a Laravel-style `app()` container accessor, so the old
  `app()` class-registry was dropped in favour of the container.

**Documentation**

- `README.md`: the "no runtime dependencies" claim and helper list were updated;
  `docs/README.md`, `docs/helpers.md`, and `docs/architecture.md` now describe
  the layered relationship with `base`, the removal of the `implementations()`/
  `app()` registry, and the relocated `Strukt\Raise` (`reset()` instead of the
  removed `clear()`).

**Tests**

- `tests/Unit/HelpersTest.php`: the "without sibling packages" description now
  reads "without optional sibling packages". No behavioural change was needed —
  the existing assertions do not cover the moved primitives.

**Public API impact**

- Breaking: the `app()` implementation registry was removed; `Strukt\Raise`
  and the duplicated primitives are no longer declared by `commons`.
- New runtime dependency: `strukt/base`. The `require` block is no longer just
  `php: >=8.2`.
